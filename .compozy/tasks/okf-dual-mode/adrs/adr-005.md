# ADR-005: A dedicated OKF conformance checker with vendored official fixtures

## Status

Accepted

## Date

2026-06-27

## Context

OKF v0.1 conformance (§9) is small and deliberately permissive: every non-reserved
`.md` must have parseable frontmatter with a non-empty `type`; `index.md`/`log.md`
must follow their shapes when present; consumers MUST tolerate broken cross-links,
unknown `type` values, and missing optional fields. ADR-002 set the product
posture: emit four producer fields and relative links, validate lenient, warn on
local standards (four fields present + `type` in the `kb.toml` vocabulary), and
offer `--strict`.

The existing lint engine (`internal/lint/lint.go:337` `schemaForPath`) is a
path-prefix switch tuned to the wiki pyramid (`wiki/concepts/`, `raw/github/`,
etc.) and parses `[[wikilinks]]` specifically (`wikilinkPattern` regex). OKF is
structurally different: a recursive tree of freeform directories where `type` is
the only hard requirement and links are markdown.

## Decision

**Implement a dedicated conformance checker in `internal/okf`**, not an extension
of `schemaForPath`.

- Recursively walk the bundle; for every non-reserved `.md`, parse frontmatter via
  `internal/frontmatter` and require a non-empty `type` (§9.2). Validate `index.md`
  (no frontmatter except an optional bundle-root `okf_version`) and `log.md`
  (ISO-date headings) shapes when present (§6/§7).
- **Lenient by default** (§9): broken links, unknown `type`, and missing optional
  fields are tolerated (not errors) — so externally produced bundles pass, which
  Phase 2 `ingest okf` depends on.
- **Local-standard warnings** on the operator's own bundle: the four producer
  fields present, and `type` ∈ `config.OKF.Types`.
- `--strict` promotes warnings to errors (CI gate).
- **Reuse `models.LintIssue` and the `internal/output` formatters** (table/json/
  tsv) for a consistent UX; a severity distinguishes error from warning.

**Fixtures (per the testing decision):** vendor the three official sample bundles
(GA4, Stack Overflow, crypto_bitcoin; Apache-2.0) into `internal/okf/testdata/` as
positive fixtures, plus synthetic negatives (missing `type`, unterminated
frontmatter, list-not-mapping frontmatter) and must-tolerate cases (broken link,
unknown `type`, frontmatter-less `index.md`). Conformance tests run behind
`//go:build integration`.

## Alternatives Considered

### Alternative 1: Extend the existing lint engine (`schemaForPath`)

- **Description**: Add OKF cases to the path-prefix switch.
- **Pros**: One lint entry point.
- **Cons**: Conflates two structurally different models (path-pyramid wiki vs
  recursive type-required OKF); the wikilink parser does not apply; a single engine
  grows two divergent rule systems.
- **Why rejected**: Separation keeps both engines simple and correct.

### Alternative 2: Maximum-rigor default (all rules hard errors)

- **Description**: Make four-field + vocabulary + link rules errors without
  `--strict`.
- **Pros**: Iron standard.
- **Cons**: Fights OKF's permissive model; rejects third-party bundles on ingest.
- **Why rejected**: Superseded by ADR-002's lenient-with-warnings posture.

### Alternative 3: Synthetic-only fixtures

- **Description**: Hand-write minimal bundles only.
- **Pros**: Smaller repo; faster tests.
- **Cons**: No validation against the bundles real OKF consumers produce/expect.
- **Why rejected**: The user chose to vendor the official bundles for maximum
  signal.

## Consequences

### Positive

- Spec-correct and tooling-compatible; high-signal conformance tests.
- Consistent CLI output via shared `LintIssue`/`output` types.
- Lenient validation unblocks Phase 2 ingest.

### Negative

- The repo grows by the vendored bundles (dozens of `.md` files).
- Two checking engines coexist (wiki lint and OKF check).

### Risks

- **Spec churn (v0.1 draft)** → isolate rules behind a versioned ruleset in
  `internal/okf`.
- **Third-party license** → keep the bundles' Apache-2.0 `LICENSE`/attribution in
  `testdata/` and document provenance.

## Implementation Notes

`okf check` returns `[]models.LintIssue` with a severity field; the CLI renders via
`internal/output`. The walker skips a full **reserved/excluded set** before applying
the `type` requirement (B-202): OKF-reserved `index.md`/`log.md`, the kb marker files
`CLAUDE.md`/`AGENTS.md` (and it does not follow symlinks, so `AGENTS.md`→`CLAUDE.md`
is not walked), and the non-concept files official bundles legitimately carry
(`README.md`, license/attribution). Without this, a freshly scaffolded bundle — which
writes `CLAUDE.md`/`AGENTS.md` — would hard-fail its own `kb okf check`, contradicting
the end-to-end test and the PRD success metric. The checker takes the resolved bundle
(topic) path; it does not
require `mode: okf` so it can validate arbitrary directories and external bundles.

**`index.md` / `log.md` ownership (N-003):** both are kb-owned. `index.md` is fully
regenerated by scaffold and by `promote` (type-grouped bullet lists); regeneration
MUST preserve the bundle-root `okf_version` frontmatter — the only place OKF permits
index frontmatter. `log.md` is append-only (kb appends a dated entry on scaffold and
promote; operators may add entries but kb never rewrites prior ones). Operators
should not hand-edit `index.md`, since the next regeneration overwrites it.
