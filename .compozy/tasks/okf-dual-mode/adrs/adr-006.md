# ADR-006: CLI surface — `kb promote` top-level and a `kb okf` command group

## Status

Accepted

## Date

2026-06-27

## Context

The MVP adds three user-facing operations now (`promote`, conformance `check`, and
a `--mode` choice on topic creation), and Phase 2 adds `export okf` and
`ingest okf`. The existing CLI (`internal/cli/root.go:14`) registers top-level
commands (`topic`, `ingest`, `lint`, `inspect`, `index`, `search`, `generate`,
`migrate`, `version`) via `command.AddCommand(...)`, shares a `--vault` persistent
flag, resolves the vault with `resolveCommandVaultPath`, and renders output through
`internal/output`. `topic new` (`topic.go`) takes positional args and has no
`--mode` flag yet.

`promote` is the daily distill verb (1 wiki doc → 1 OKF concept); `check`,
`export`, and `ingest` are OKF-ecosystem operations.

## Decision

- **`kb promote <wiki-doc> --to <topic> --type <Type> [--description <text>]`** as a
  **top-level** command — it is the daily verb and deserves prominence. `--to` must
  resolve to a `mode: okf` topic or `promote` errors (N-202).
- **`kb okf`** as a parent command **group**:
  - MVP: `kb okf check <topic> [--strict] [--format table|json|tsv]`.
  - Phase 2: `kb okf export <topic> [...]`, `kb okf ingest <bundle> --to <topic>`.
- **`kb topic new`** gains `--mode wiki|okf` (default `wiki`).

All new commands follow the existing cobra patterns: built in `internal/cli`,
registered via `AddCommand`, resolving the vault through `resolveCommandVaultPath`,
delegating business logic to `internal/okf`, and rendering via `internal/output`.

## Alternatives Considered

### Alternative 1: Everything under `kb okf`

- **Description**: `kb okf promote|check|export|ingest`.
- **Pros**: Maximum namespace cohesion.
- **Cons**: Buries `promote` — the most-used verb — one level deeper.
- **Why rejected**: Daily ergonomics beat namespace purity for the hot verb.

### Alternative 2: `kb promote` + `kb lint --okf`

- **Description**: Conformance as a flag on the existing `lint`.
- **Pros**: Reuses `lint`.
- **Cons**: Mixes two engines (wiki pyramid vs OKF conformance) in one command and
  gives no natural home to Phase 2's `export`/`ingest`.
- **Why rejected**: ADR-005 keeps the engines separate; the `okf` group hosts the
  whole ecosystem.

## Consequences

### Positive

- Discoverable `kb okf …` namespace that grows cleanly across phases.
- The daily verb stays one keystroke deep.
- Reuses vault resolution, flags, and output formatting conventions.

### Negative

- Two entry points for OKF (`kb promote` and `kb okf …`) — mitigated by docs and
  `--help` cross-references.

### Risks

- **`--mode` typos / invalid values** → validate against `{wiki, okf}` at parse
  time with a clear error.

## Implementation Notes

`newPromoteCommand` and `newOKFCommand` (with a `check` subcommand) are added to
`newRootCommand`. `topic new` adds `command.Flags().StringVar(&mode, "mode",
"wiki", …)` and passes it into topic creation (ADR-003). Output uses
`output.OutputFormat*` like `lint`.
